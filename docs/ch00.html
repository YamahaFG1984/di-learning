导读

一本 2009 年的书，为什么今天仍然值得读

这本书讲的不是 Spring 的 API，而是「谁来负责构造对象」这个问题的完整解空间：构造顺序、状态归属、行为织入、可测试性。API 会过时，这些约束不会。所以本讲义的做法是——原理照讲，代码全部翻新。

  • Java · Spring 2.5 · Guice 2.0 · PicoContainer
  • 对照 Spring 7 / Boot 4 · Guice 7 · Jakarta EE 11

0.3本讲义怎么读

每一章的结构是固定的：

  • 主旨句 —— 一句话说清这一章在回答什么问题；
  • 正文 —— 原书论证的重写，配机制图；代码用现代写法，遇到 2009 年的写法会明确标注；
  • ⚠ 陷阱框 —— 原书踩过的坑，红色边线；
  • 2026 对照框 —— 这一章的结论在今天成立到什么程度、哪些 API 已经换掉，青色边线。

如果你只想知道"哪些东西过时了"，直接跳到 附录 A：2009 → 2026 迁移总表。

先说结论：什么变了，什么没变

没变的（占全书 80%）：构造器注入优先、不可变字段、作用域越界（scope-widening）的危害、单例必须线程安全、循环依赖是设计信号、代理无法拦截 final/private/static、松耦合靠接口契约、集成测试补单元测试的盲区。这些是语言和运行时的性质，不是框架的选择。

变了的（占 20%，但很显眼）：XML 配置基本消失、javax.* 全体迁到 jakarta.*、书里推荐的三个库（warp-persist / Sitebricks / PicoContainer）已全部停更、编译期 DI（Dagger/Micronaut/Quarkus）成了运行时反射之外的第二条主流路线、ThreadLocal 作用域在虚拟线程时代有了替代品 ScopedValue。
