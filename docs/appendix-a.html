A.1最重要的一件事：javax → jakarta

⚠ 这会影响你读到的每一段代码

2017 年 Oracle 把 Java EE 捐给 Eclipse 基金会，但不允许继续使用 javax 包名。于是 Jakarta EE 9（2020）做了一次"大爆炸"式重命名：所有 javax.* 一律改为 jakarta.*，没有中间过渡方案。

书里的 import今天的 import用途
javax.inject.Injectjakarta.inject.InjectJSR-330 标准注入注解
javax.inject.Providerjakarta.inject.Provider第 3 章的 Provider 模式
javax.servlet.*jakarta.servlet.*第 5、7、11 章的 Web 层
javax.persistence.*jakarta.persistence.*第 8、11 章的 JPA
javax.validation.*jakarta.validation.*第 10 章的 JSR-303
javax.annotation.PostConstructjakarta.annotation.PostConstruct第 7 章；Java 11 起已从 JDK 移除，需单独加依赖
com.google.inject.Inject仍在，但优先用 jakarta.inject.InjectGuice 7 只认 jakarta 命名空间

A.5结论的存活率

章核心结论2026
1手工构造 / 工厂 / 服务定位器各有死穴；注入器只在入口调用一次完全成立
2组合键（类型 + 限定注解）优于纯字符串或纯类型完全成立，已标准化为 @Qualifier
3构造器注入优先；setter 只在不得已时用完全成立，已是行业默认
3循环引用用代理打破推翻：Spring Boot 2.6 起默认禁止循环依赖
3字段注入"实践中价值很小"完全成立，IDE 直接报 warning
4单元测试里不要启动容器完全成立，测试切片就是为此设计
4集成测试要贴近生产环境加强：Testcontainers 让"贴近"变成"就是"
5单例反模式 vs 单例作用域完全成立
5请求作用域基于 thread-per-request部分失效：响应式栈没有这个前提
6按问题域设计自定义作用域态度转向保守：优先显式传参
6scope-widening 的四类事故完全成立，仍是最难查的一类 bug
7生命周期是领域相关的；析构反模式完全成立
7多播生命周期进化成应用事件（@EventListener）
8代理拦不到 static / private / final / 字段完全成立，另加"自调用"一条
8拦截器顺序需要纵向集成测试成立，另有 @Order 可显式控制
9final 保证安全发布完全成立，虚拟线程时代更重要
9五道不可变性谜题谜题 1 被 record 消灭，2–5 全部存活
9ConcurrentHashMap 用条带锁技术细节过时：Java 8 已改为 CAS + 桶级锁
10刚性配置反模式成立；@ConfigurationProperties 是标准解
10框架应提供程序化配置扩展点已成行业默认（各种 Customizer）
11请求作用域的页面对象转向无状态控制器 + 参数传递
